# 离线部署说明

联网准备环境按目标架构运行 `TARGET_ARCH=arm64 ./prepare-offline-bundle.sh` 或 `TARGET_ARCH=amd64 ./prepare-offline-bundle.sh`；目标服务器只运行 `sudo ./deploy.sh`。目标服务器无需预装 Docker Engine、Docker Compose 或 jq，两个目标架构包都内置固定版本且带 SHA256 校验的安装资产。服务器缺少 jq 时，部署脚本会自动安装到 `HOST_TOOLS_INSTALL_DIR`（默认 `/usr/local/bin`）。目标服务器仍需具备 bash、curl、openssl、zstd、tar、sha256sum 和常见 Linux 基础命令；部署前检查会逐项明确报告缺失命令。

Docker 检测和处理顺序如下：

1. Docker Engine、守护进程和 Compose v2 都可用：直接复用，不修改现有安装；
2. Docker CLI 存在但守护进程未运行：尝试通过现有 systemd/SysV 服务启动，失败则保留现场并停止；
3. Engine 可用但 Compose v2 缺失（包括只有旧版 `docker-compose` v1）：只安装包内 Compose v2 插件；
4. Docker 完全缺失：核验 `runtime/docker/checksums.sha256` 后安装静态 Engine 和 Compose，注册 systemd 或 SysV 开机服务；
5. 新安装 Engine 的数据目录默认是 `${DATA_ROOT}/docker-engine`，即默认 `/TRS/lxAI/docker-engine`。

设置 `DOCKER_AUTO_INSTALL=false` 可改为只检测不安装；`DOCKER_DATA_ROOT`、`DOCKER_INSTALL_DIR` 和 `DOCKER_COMPOSE_PLUGIN_DIR` 可按服务器规范调整。现有 Docker 的数据目录不会被修改。

部署脚本在导入镜像前执行 `sha256sum -c checksums.sha256`，任何不一致都会中止；随后根据包内 `TARGET_ARCH` 核对服务器与逐个镜像的 Architecture，架构不一致会中止。Compose 使用 `--pull never --no-build`，因此不会联网拉取或构建。

部署参数统一放在 `config/deployment.env`（可从 `.example` 复制），也可用 `deploy.sh` 命令行参数覆盖。`WEB_PORT` 指定首选端口；`WEB_PORT_CONFLICT_POLICY=next` 会检查主机监听状态并自动递增，`fail` 则立即停止。模型 URL、模型完整名称、可选 API Key、持久化目录、监听地址、时区、安全开关、资源上限及预检阈值均可配置。

默认不扫描或修改模型 Runtime。需要只读自动探测时设置 `MODEL_AUTO_DETECT=true`；未启用时严格使用 `MODEL_BASE_URL` 和 `MODEL_NAME`。持久化目录必须是至少两级的专用绝对路径，危险系统路径会被拒绝。
